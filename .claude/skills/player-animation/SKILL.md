# Player animations from Blender

The FBX (Quaternius "Animated Human", CC0) only ships Idle, Walk, Run, Jump, Punch, Working
and Death. Every other clip is generated by Python in Blender, so it's repeatable and needs
no third-party licence. (Mixamo clips aren't CC0; don't use them.)

| Clip | Library (`characters/human/`) | Blender action / NLA track | Script |
|---|---|---|---|
| tread, crawl | `swim_animations.res` | SwimTread, SwimCrawl / `swim_tread`, `swim_crawl` | `swim_clips.py` |
| down, idle | `sit_animations.res` | SitDown, SitIdle / `sit_down`, `sit_idle` | `sit_clips.py` |
| up | `pick_animations.res` | PickUp / `pick_up` | `pick_clips.py` |
| overhand | `throw_animations.res` | Throw / `throw` | `throw_clips.py` |

## The Blender file

`/Users/keshara/dev/blender-dev/outbound/player-swim.blend`, **outside the repo**. It holds a
Blender import of `human.fbx` (armature `Human Armature`, mesh `Human_Mesh`) and the clip
scripts as text blocks. The versioned copies are in `tools/blender/` (same file names).
After editing a text block, write it back there (see `tools/blender/README.md`), and if the
.blend is missing or stale, load them from there. The scripts:

- `swim_tools.py`, the shared base:
  - `U, F, L` is the body frame: up, forward, left.
  - `solve(base, aims, extra)` turns aim directions into bone rotations.
  - `idle_basis()` gives the Idle clip's first frame, used as the rest of the body.
  - `make_clip`, `_fcurves` (handles Blender 5's layered actions) and `nz`.
- `sit_clips.py` adds the IK-style helpers that the other clips reuse by exec'ing it:
  - `P(l, f, u)` gives a point in the body frame.
  - `lean(a)` tilts U towards F.
  - `curve(waypoints, t)` is a Hermite curve through waypoints.
  - `smooth`.
  - `two_bone(root, target, l1, l2, pole)` is analytic two-bone IK.
  - `apply(rots, hips_world)` poses the rig.
  - `head(bone)` gives a joint's world position.
  - `measure(base)` gives limb lengths and the Idle feet.
  - `key` and `make(name, frames, fn, loop)`.
- One `*_clips.py` per feature, each with a `build()` that regenerates its actions.

Run code there with `mcp__blender__execute_blender_code`. Look at the result with
`mcp__blender__look` (`mode="frames"`, explicit frame numbers, a side or three-quarter
`view`).

### Frame and units

- **Body frame:** U=(0,0,1), F=(0,-1,0) and L=(1,0,0) are hardcoded and are the game's facing.
  Never derive them from the hips: the FBX's hips sit about 43° off. Getting this wrong made
  the crawl roll onto one side.
- **Units:** the rig is about 5.3 units tall, with the ground at z=0. In game it's scaled by
  0.338 (`scenes/player.tscn`), so 1 m in game is 2.96 Blender units.
- **Clip rate:** 30 fps. Loops key their last frame equal to the first.
- **Pose bones:** a pose function returns `aims`, a dict from bone name to a direction or a
  `(Y dir, X dir)` pair. Fully orient Hips, Spine, Spine1, Spine2, Neck and Head with `(dir, L)`
  so the Idle stance's twist doesn't leak in. Limbs come from `two_bone` towards world targets.
  Solve the torso and `apply` it first, so `head("RightArm")` and similar return the real joint
  positions.
- **Hips height:** key the Hips location through `apply`/`key` to lower or raise the body.

## Authoring steps

1. **Prepare the rig:** set `ARM.animation_data.use_nla = False`. The rig must keep its
   imported, untilted transform: rotation X 90°, scale 0.692.
2. **Write the clip:** put it in a new or existing text block (`t.clear(); t.write(src)`) and
   call its `build()`.
3. **Check contacts numerically:** evaluate `Human_Mesh` (`evaluated_get(...).to_mesh()`) and
   take the minimum z of the vertices whose strongest group is the pelvis, feet or hands bones.
   Seated or planted parts should be within about 0 to 2 cm of the ground. Idle's feet sit
   about −0.05 units, so match that.
4. **Check visually:** add a temporary prop (e.g. a sphere for a coconut) at the target if it
   helps, look at 6 to 8 frames, then **delete the prop**.
5. **Set up NLA tracks:** set `use_nla = True` and `action = None`. Give each clip its own
   track and strip named as in the table, with `strip.frame_start_ui = 0`. Remove an old track
   with the same name first.
6. **Export:** select only the armature and the mesh, then run:
   ```python
   bpy.ops.export_scene.gltf(filepath="<scratchpad>/anim_source.glb", export_format="GLB",
       use_selection=True, export_animation_mode="NLA_TRACKS", export_force_sampling=True,
       export_def_bones=False, export_anim_single_armature=True)
   ```
   The `check_idle` track must stay, because the converter verifies against it. Save the
   .blend with `bpy.ops.wm.save_mainfile()`.
7. **Convert:** add the clip to `CLIPS` in `tools/convert_anims.gd` as
   `glb track -> [library, clip, loops]`, then run:
   ```sh
   Godot --headless --path . --script res://tools/convert_anims.gd -- --in=<scratchpad>/anim_source.glb
   ```
   - "Idle check" must pass (about 0.0007 rad). If it doesn't, the rig was tilted or moved.
   - It writes every library. `git status` should show only the ones you meant to change.

## Wiring into player.gd

Follow the swim, sit and pick code:

- **Load:** `const X_ANIMS = preload(...)`, then `player.add_animation_library("x", X_ANIMS)` in
  `_build_animation_tree`.
- **Graph:** add an `AnimationNodeAnimation` (`_clip("x/clip")`) and an `AnimationNodeTimeSeek`,
  and connect `graph.connect_node("x_seek", 0, "x")`.
  - Connect the state transition's input to the **seek** node, never the clip node. Wiring it
    to the clip node leaves the clip frozen on frame 0.
- **Driving the clip:** add `state.add_input("x")`. Each frame, set
  `parameters/x_seek/seek_request` to a time the controller owns. That allows playing
  backwards (standing up is the sit-down reversed) and exact event timing.
- **Advance the clip time in one place only** (`_process`). Advancing it in
  `_physics_process` too skips threshold events such as the pick's grab.
- **Transitions:** `_walk` calls `_update_animation`, which requests `ground` or `air` every
  physics frame. A new state needs its own branch in `_physics_process` (like `_sitting` and
  `_picking`), and must request `ground` itself when it ends.
- **Contacts in the world:** a contact the game relies on must match the clip. For example,
  `PICK_REACH` in metres is `GRAB` in `pick_clips.py` × 0.338. Keep the facing the target was
  worked out for. Turning to face the target afterwards swung the hand 10 cm off.
- **Upper-body clips** that should play on the move (like the throw) don't get a state.
  They go through the filtered `upper_body` Blend2 after the state machine: its filter takes
  the bones whose names contain an entry of `UPPER_BODY`. Key the clip's hips and legs
  neutral.
- **Holding things:** to hold an item, use the `RightHand` `BoneAttachment3D` (`hand`). Place
  the item at its world transform, then `reparent(hand, true)`.

## Verify in game

Follow the `godot-verify` skill. Write a temporary `res://tools/tmp/*.gd` SceneTree script
that:

1. Loads the main scene and puts the player somewhere fitting (a beach spot, or next to
   `Pickups.items[k]`).
2. Triggers the action, calling the player method or feeding an `InputEventAction` to the
   handler.
3. Prints bone heights above `world.get_height()` (via `Skeleton3D.get_bone_global_pose`) and
   gaps to any target, broken into right, forward and up in the model frame.
4. Saves side-camera screenshots at key moments.

Run it windowed with `--audio-driver Dummy`, check the numbers and images, then delete the
script and its `.uid`. If the game doesn't measure what Blender showed, check the wiring
before re-posing.

Finally, copy any changed text blocks to `tools/blender/`, and update the player paragraph in
CLAUDE.md and the README controls if a key was added.
